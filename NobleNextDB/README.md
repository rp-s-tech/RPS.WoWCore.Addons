# NobleNextDB

Справочник внешности кастомных NPC для NobleNext. Это один пакет с `LoadOnDemand`, который подключается при открытии редактора внешности. Внутри находятся метаданные рас и классов, загрузчик и файлы `creature_templates/<race>/<race>_male.lua` и `<race>_female.lua`. Для каждой расы отдельный аддон не нужен.

Пакет не использует SavedVariables. Глобальный API называется `NobleNextData`; существующая таблица настроек `NobleNextDB` основного аддона не изменяется.

## Источник данных

Каталог генерируется из проверенного пакета `noble-site/ng-sp-data/generated`: метка `build_id` **63534**, locale **ruRU**, SHA-256 пакета указан в `creature_templates/provenance.json`. Генератор проверяет checksum манифеста, размеры и SHA-256 используемых CSV, согласованность метки build и locale строк. Исходный экспортёр вычисляет эту метку по заголовкам `Field_*`; она не доказывает исходную версию клиента. `build_id_origin` фиксирует это ограничение. Текущий `CSVData` может отличаться от исходной выгрузки и не смешивается с пакетом сайта.

Список **30 рас** соответствует текущему select сайта: 29 стандартных ID из `CustomNpcRaceCatalog` плюс расы, используемые в `creature_template_outfits`, с пересечением по справочнику. Снимок `tools/customnpc-races.snapshot.json` содержит проверенные read-only списки ID, время проверки, SHA политики сайта и checksum справочника. Сейчас использование в world добавляет race `91`; race `86` в этом списке отсутствует. Изменение используемых рас в world требует обновить снимок и перегенерировать каталог. Генератор сам к БД не подключается.

Сохраняются исходные `option_id`, `choice_id`, названия, порядок, параметры рас/моделей, классовые и расовые маски, `requirement_id` и связи обязательных выборов. Части маски рас хранятся исходными десятичными строками, без объединения в число Lua и изменения знака. `visual_requirement_id` относится к отдельной таблице `ChrCustomizationVisReq`; её строки отсутствуют в исходном пакете, поэтому это поле сохраняется без локального вычисления доступности. Итоговую доступность и право изменения определяет сервер.

Файлы содержат обычные именованные Lua-таблицы внутри функции регистрации. Вызов `emit("option", { option_id = 10, ... })` добавляет параметр, `emit("choice", { choice_id = 20, option_id = 10, ... })` — его вариант. Таблицы создаются при выполнении выбранной функции, а не при загрузке файлов. Ключи являются исходными числовыми ID; универсальный параметр `skin` не вводится, поскольку набор параметров зависит от расы и пола.

## API и жизненный цикл

После загрузки `C_AddOns.LoadAddOn("NobleNextDB")`:

```lua
local lease = NobleNextData.AcquireModel(raceId, sex, function(data, reason)
    if not data then return end
    local model = data.models[sex]
    local option = model and model.optionsById[optionId]
    local choice = option and option.choicesById[choiceId]
end)
-- При смене NPC/образа и закрытии панели:
if lease then lease:Release() end
```

Callback вызывается асинхронно. Несколько запросов одной пары раса/пол разделяют разворачивание данных. В ответе присутствует только запрошенный `data.models[sex]`; другой пол не разворачивается. `Release()` отменяет ещё не доставленный callback; последний release удаляет ссылки загрузчика на развёрнутые таблицы этой модели и останавливает незавершённое создание. Потребитель также должен убрать собственные ссылки на `data`, `model`, `option` и `choice`. Каталог предназначен только для чтения.

`LoadAddOn` в WoW синхронный: при первом подключении `NobleNextDB` читаются и компилируются все его файлы. 60 файлов моделей занимают около 2,9 МБ исходного текста; это не оценка памяти клиента. В отдельные кадры разбито выполнение выбранной функции: до 40 записей или около 2 мс за порцию, затем продолжение через `C_Timer.After`. В бою разворачивание откладывается до `PLAYER_REGEN_ENABLED`. WoW не выгружает загруженный аддон; скомпилированные функции и строковые константы остаются до перезагрузки интерфейса. Освобождаются развёрнутые таблицы, а не весь код пакета.

- `GetMetadata()` возвращает build, locale, schemaVersion и checksum источника.
- `GetRaceList()` возвращает лёгкий список рас без загрузки их внешности.
- `GetClasses()` возвращает строки справочника классов; числовые CSV-поля здесь представлены строками.
- `AcquireModel(raceId, sex, callback)` возвращает lease; callback получает `data` либо `nil, reason`.
- `data.race_id` и `data.sex` задают выбранную модель. `data.models[sex].optionsById[optionId].choicesById[choiceId]` даёт прямой доступ по исходным ID; массивы `options` и `choices` сохраняют порядок отображения.
- `data.requirementsById` и `requiredChoicesByRequirement` дают исходные зависимости.
- `EvaluateOption(data, sex, optionId, classId, selectedByOption)` и `EvaluateChoice(data, sex, optionId, choiceId, classId, selectedByOption)` проверяют известные локальные ограничения. `selectedByOption` содержит исходные ID: `{[optionId] = choiceId}`.
- `GetCacheStats()` возвращает `sourceModels`, `decodedModels`, `pendingModels` и `leases`; это счётчики зарегистрированных функций, развёрнутых моделей, заданий и потребителей, а не замер всей памяти Lua.

Результат локальной проверки: `true` — известные правила выполнены; `false` с `class_required`, `race_required` или `choice_required` — известное ограничение; `nil, "server_required"` — данных или контекста недостаточно. Нужен класс самого NPC; класс игрока и условное значение `1` не подставляются. Правила повторяют проверку Custom NPC в `RolePlayCustomNpcOps.cpp`: флаг `HasRequirements`, маски класса/расы и зависимости OR внутри одного параметра, AND между параметрами. Связь `ReqType` с native `Flags` подтверждена структурой layout `CA154412`, `DB2LoadInfo` и исходным экспортёром. Достижения, задания, предметные разблокировки и `ChrCustomizationVisReq` здесь не проверяются, как и в native-проверке Custom NPC. Неизвестные зависимости другой модели и несовпадение расового bit mapping требуют ответа сервера. Локальный результат не подтверждает серверные права и не заменяет применение с серверной валидацией.

Причины отказа запроса модели: `unknown_race`, `unknown_model`, `invalid_catalog`. Без таймера `AcquireModel` возвращает `nil, "timer_unavailable"`. Ошибку первоначального `LoadAddOn("NobleNextDB")` обрабатывает вызывающая панель.
